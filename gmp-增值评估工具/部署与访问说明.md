# 部署与访问说明

## 一、先说结论：这个网址能不能发给别人？

| 场景 | 能不能用 | 说明 |
|---|---|---|
| **同一局域网**（同一个路由器 / 同一个 WiFi） | ✅ 能 | 发 `http://<你的局域网IP>:8780/` |
| 手机流量 / 公司外网 / 不同楼层的 WiFi | ❌ 不能 | 这是本机跑的服务，没有公网入口 |
| 你的电脑关机 / 休眠 / 服务退出 | ❌ 不能 | 没人跑服务就没人提供服务 |

**判断是否同一网络**：手机连上和电脑**同一个 WiFi**，浏览器打开上面的地址能出登录页 = 能用。

---

## 二、第一次需要做的一件事：放行防火墙端口

Windows 防火墙默认会拦掉 8780 端口，导致同事「打不开网页」。

**方法一（推荐，最省事）**

右键 `打开评估工具.cmd` → **以管理员身份运行** → 脚本会自动放行端口，并在窗口里显示局域网地址。

**方法二**

以管理员身份打开 PowerShell，粘贴执行：

```powershell
netsh advfirewall firewall add rule name="GMP Audit Tool 8780" dir=in action=allow protocol=TCP localport=8780 profile=any
```

> 只想放行局域网、不想暴露到公用网络的话，把上面的 `profile=any` 改成 `profile=private`。

---

## 三、日常怎么用

1. 双击 `打开评估工具.cmd`（首次请用管理员身份）
2. 窗口里会显示两个地址：
   - **本机地址** `http://127.0.0.1:8780/` —— 自己用
   - **局域网地址** `http://192.168.x.x:8780/` —— **发给同事用这个**
3. 浏览器自动打开登录页

### 账号怎么来的

| 角色 | 账号 | 密码 |
|---|---|---|
| 管理员 | `admin` | 见 `server/.env` 的 `DEFAULT_ADMIN_PASSWORD` |
| 组长 | 上传Word 计划时自动创建 | 首次在登录页「注册账号」设手机号+密码 |
| 审核员 | **计划里出现谁就自动建谁** | 同上，用**本人姓名**登录 |

**审核员不用组长建账号**：拿到姓名后在登录页点「注册账号」，填姓名（须与审核计划一致）+ 手机号 + 密码即可。

## 四、给别一台电脑装一份（换机或多人使用）

```bash
# 1. 装依赖
cd server && npm install
cd ../web && npm install

# 2. 配环境变量
cp server/.env.example server/.env    # Windows: copy
#   然后编辑 server/.env，至少改这两项：
#   JWT_SECRET=  → 改成随机长字符串
#     生成：node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
#   DEFAULT_ADMIN_PASSWORD=  → 改成你自己的密码

# 3. 建库（首次）
cd server && npx prisma migrate deploy && npm run seed

# 4. 构建前端
cd ../web && npm run build

# 5. 启动
cd ../ && 打开评估工具.cmd
```

### 换机时别忘了迁移数据

业务数据全在 `server/prisma/v2.db` 这个文件里（SQLite），**它不在 Git 仓库中**。
换机器时单独拷过去，或用 `server/prisma/` 下已有的备份文件。

## 五、⚠️ 安全须知（多人共用时必读）

1. **`.env` 不在仓库里**。里面是admin 密码与JWT 密钥，泄露等于任何人都能当管理员。
2. **首次部署务必改掉默认 JWT_SECRET 与管理员密码**，否则等于开着大门。
3. **本服务没有 HTTPS**，仅建议在**可信局域网**内使用，不要直接暴露到公网。
4. **项目数据严格隔离**：每个人只能看到自己参与的项目，跨项目访问会被拒绝。
5. 若要长期对外提供服务，建议改为 Docker 部署（仓库已含 `docker-compose.yml`）并加反向代理 + HTTPS。

## 六、常见问题

**Q：同事说打不开这个网址**
A：九成是防火墙。按第二节放行端口后再试。

**Q：同事能打开，但登录提示"账号不存在"**
A：他的姓名没被识别到。让他点「注册账号」用**与审核计划完全一致的姓名**注册即可。

**Q：换了一台电脑，登录后看不到之前的项目**
A：数据库没迁过去。`server/prisma/v2.db` 是本机文件，需要单独拷贝。

**Q：端口被占用了**
A：改 `server/.env` 里的 `PORT`，同时改 `打开评估工具.cmd` 里对应的 `PORT` 变量。

**Q：能不能让不在公司的人也能用？**
A：当前架构不行。需要部署到有公网地址的服务器（或用内网穿透），并补上 HTTPS。当前版本定位是局域网工具。

### 本机网络需注意

这台机器的 git 配了 `insteadOf` 规则，把 `github.com` 自动改写到 `gh-proxy.com`。
所以 `git` 操作能走通，但 `gh auth login`（浏览器授权）会失败——代理不转发设备码接口。

实测结论（2026-10-09）：

| 通道 | 实测结果 |
|---|---|
| `api.github.com` | 200，可达（但设备码端点不在此域名下） |
| `github.com/login/device/code` | 超时 / 502，被代理拦截 |
| `github.com:443` | 不可达 |
| `github.com:22`（SSH） | **可连接** |

**结论：本机推送一律走 SSH。** 下面方式二已经配置好，只需粘贴一次公钥。
