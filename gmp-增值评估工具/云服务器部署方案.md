# 云服务器部署方案

> 目标：让同事在**任何网络、任何时间**都能打开这个工具，不依赖您这台电脑。
>
> 与原工具的区别：原工具是单个 HTML 文件，GitHub Pages 免费托管；
> 本产品有后端与数据库，必须跑在一台**7×24 在线**的服务器上。

---

## 一、方案对比

| 方案 | 费用 | 关机影响 | 推荐度 |
|---|---|---|---|
| **A. 云服务器**（本方案） | 约 40~80 元/月 | **不受影响** | ✅ 推荐 |
| B. 内网穿透 | 免费~30元/月 | 您的电脑关了就连不上 | ⚠️ 临时演示可用 |
| C. 只在局域网用| 0 | 您的电脑关了就连不上 | ❌ 不满足需求 |

**为什么选云服务器**：审核员在企业现场跑，**未必跟您同一个网络**；而且审核报告涉及客户数据，放在云上比放在家里电脑上更安全（不依赖个人电脑的开关与网络）。

---

## 二、买什么服务器

| 项目 | 建议 | 说明 |
|---|---|---|
| 厂商 | 阿里云 / 腾讯云 / 华为云均可 | 选离审核现场近的地域 |
| 配置 | **2核 2G**，系统 Ubuntu 22.04 | 够跑，本工具很轻 |
| 系统盘 | 40G SSD | 含系统 + 应用 + 数据库 |
| 带宽 | 1~3 Mbps 固定带宽 | 够几十人同时用 |
| 预期月费 | **40~80 元** | 活动期新用户常有首年优惠 |

**推荐轻量应用服务器（ECS/Lighthouse）**，比 ECS 便宜、开通快。

### ★ 两个端口别搞混（自己踩过）

| 场景 | 访问端口 | 来源 |
|---|---|---|
| **本机 /局域网**（开发模式） | **8780** | 直接跑 `tsx src/index.ts`，前后端同一端口 |
| **云服务器**（Docker 模式） | **8080** | `docker-compose.yml` 里 `ports: "8080:80"` |

Docker 模式下前端 nginx 在容器内监听 80，对外映射到 **8080**；
nginx 已配好 `/api/` 反向代理到后端容器，所以**只需要访问一个端口**，不用管 3000。
**云端只需在安全组放行 8080**（不必放行 8780 / 3000）。

## 三、部署步骤

### 步骤 1 · 准备环境

登录服务器（Windows 用 Xshell/PuTTY，Mac 用终端）：

```bash
# 安装 Node.js 22
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt-get install -y nodejs

# 确认版本
node -v   # 应为 v22.x
```

### 步骤 2 · 上传代码

在服务器上：

```bash
mkdir -p /opt/gmp && cd /opt/gmp
# 用 git 拉取（仓库是私有的，需先配好SSH 或改用上传方式）
git clone git@github.com:218451/gmp-tool.git .
cd gmp-增值评估工具
```

> 仓库当前是**私有**。若想让部署更简单，可在 GitHub 仓库设置里
> 临时改为 Private→ 保持不变 + 在服务器配 deploy key（只读）。

### 步骤 3 · 配置环境变量

```bash
cd /opt/gmp/gmp-增值评估工具/server
cp .env.example .env

# 生成强随机密钥
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

vi .env
# 至少改这三项：
#   DATABASE_URL="file:./v2.db"
#   JWT_SECRET="<上面生成的 64 位随机串>"
#   DEFAULT_ADMIN_PASSWORD="<您自己设的强密码>"
```

> ⚠️ **强烈建议现在换掉 admin 密码**：旧密码明文曾出现在启动脚本与文档中。

### 步骤 4 · 启动

```bash
cd /opt/gmp/gmp-增值评估工具/server
npm install
npx prisma db push --skip-generate
npx tsx prisma/seed.ts          # 灌入 200 条指导原则数据
cd ../web && npm install && npm run build
cd ../server && npx tsx src/index.ts
```

访问 `http://服务器IP:8780/` 确认能打开。

> 📌 上面这条是**手动 pm2 部署**（开发模式），端口 8780。
> **更推荐用 Docker**，见步骤 4B，端口是 8080，且 nginx 已配好 API 代理。

---

### 步骤 4B · 【推荐】用 Docker 部署

比步骤 4 简单，不用管 Node、nginx、pm2 三套东西。

```bash
cd /opt/gmp/gmp-增值评估工具

# 1. 造.env（Docker 读这个文件，不读 server/.env）
cat > .env << 'EOF'
JWT_SECRET=<node -e "console.log(require('crypto').randomBytes(32).toString('hex'))" 的输出>
DEFAULT_ADMIN_PASSWORD=<你自己设的强密码>
DEEPSEEK_API_KEY=<留空则用规则引擎，不影响功能>
EOF

# 2. 起服务（首次会自动build 镜像，约 3~5 分钟）
docker compose up -d --build

# 3. 看状态
docker compose ps        # 两个都应是 healthy / Up
curl http://127.0.0.1:8080/api/health   # 应返回 {"ok":true,...}
```

**访问**：`http://服务器IP:8080/`

**数据持久化**：数据库在命名卷 `gmp_data`（容器内 `/data/gmp.db`）。
`docker compose down` 不会丢数据，**但 `docker compose down -v` 会删库** —— 别加 `-v`。

**升级代码后**：
```bash
cd /opt/gmp && git pull
cd gmp-增值评估工具 && docker compose up -d --build
```

### 步骤 5 · 配开机自启（重要）

否则重启服务器后服务不会自动起来：

```bash
npm install -g pm2
cd /opt/gmp/gmp-增值评估工具/server
pm2 start src/index.ts --name gmp-audit --interpreter npx --interpreter-args "tsx"
pm2 save
pm2 startup# 按提示执行它给出的那条命令
```

### 步骤 6 · 开防火墙 + 域名 HTTPS

**服务器自身的安全组**放行端口（腾讯云/阿里云控制台里配，不是 Windows 防火墙）：

| 端口 | 用途 |
|---|---|
| 22 | SSH |
| **8080** | **本工具的访问端口**（Docker 模式） |
| 80 / 443 | 若以后绑域名 + 配 HTTPS 才需要 |

系统防火墙：

```bash
ufw allow 22/tcp && ufw allow 8080/tcp
ufw enable
```

> 若改用步骤 4 的手动 pm2 部署，则放行 **8780**。

### 步骤 7 · 备份数据库（务必做）

数据库是全部业务数据，**丢了就找不回来**：

```bash
mkdir -p /opt/gmp/backup
cat > /opt/gmp/backup.sh << 'EOF'
#!/bin/bash
cd /opt/gmp/gmp-增值评估工具/server
cp prisma/v2.db "/opt/gmp/backup/v2-$(date +%Y%m%d-%H%M).db"
find /opt/gmp/backup -name "v2-*.db" -mtime +30 -delete
EOF
chmod +x /opt/gmp/backup.sh

# 每天凌晨 3 点自动备份
crontab -e
# 加一行：
# 0 3 * * * /opt/gmp/backup.sh
```

> 💡 更稳妥：把备份同步到对象存储或另一台机器。**只存在同一台服务器上不算备份。**

## 四、部署后验证清单

> 下表按 **Docker 部署（端口 8080）** 写。若用手动 pm2 部署，把 8080 换成 8780。

| 检查项 | 预期 | 命令 |
|---|---|---|
| 容器都在跑 | 两个 Up | `docker compose ps` |
| 服务在跑 | 200 | `curl http://127.0.0.1:8080/api/health` |
| 数据库连上 | `"db":"up"` | 同上，看返回内容 |
| 指导原则已灌 | 200 条 | 登录后看条款分级页 |
| 数据持久化 | 重启后数据还在 | `docker compose restart`后再查|
| 备份已配置 | 定时任务存在 | `crontab -l` |
| 外网可访问 | 手机流量能打开 | `http://<服务器IP>:8080/` |

> 📌 **Docker 模式不需要执行 seed**。`docker-compose.yml` 里后端容器启动时会自动
> 把 200 条指导原则灌进空库。手动 pm2 模式才需要 `npx tsx prisma/seed.ts`。

## 五、常见问题

**Q：忘了 admin 密码怎么重置**

最省事的办法是改 `.env` 里的 `DEFAULT_ADMIN_PASSWORD`，然后重启容器——
后端启动时会用它覆盖 admin 的密码。

```bash
cd /opt/gmp/gmp-增值评估工具
vi .env                 # 改 DEFAULT_ADMIN_PASSWORD
docker compose up -d --force-recreate server
```

不想改文件的话，直接进容器改数据库（注意数据库在命名卷 `gmp_data`）：
```bash
docker compose exec server npx tsx -e "
import b from 'bcryptjs'; import {PrismaClient} from '@prisma/client';
const p = new PrismaClient();
(async () => {
  await p.user.update({ where: { username: 'admin' },
    data: { passwordHash: b.hashSync('你的新密码', 10) } });
  await p.\$disconnect(); console.log('已重置');
})()"
```

**Q：启动报better-sqlite3 编译失败**
手动 pm2 部署才会遇到，装构建工具：`apt-get install -y python3 make g++`。
用 Docker 不会有这个问题（镜像已用 bookworm 并预装工具链）。

**Q：AI 报告不生成**
服务器上没配 DeepSeek Key，系统会自动降级为规则引擎，**功能不受影响**，只是分析文本没那么灵活。

**Q：忘记 admin 密码 / 想改数据库**
见本章第一条。**永远不要用 `docker compose down -v`**，`-v` 会删掉数据库命名卷。

**Q：代码更新了怎么生效**
```bash
cd /opt/gmp && git pull
cd gmp-增值评估工具 && docker compose up -d --build
```

## 六、安全提醒

1. **admin 密码务必更换**，旧密码已暴露过
2. **`.env` 不要提交到 Git**，仓库已配 `.gitignore`
3. **不要把数据库文件 `v2.db` 传到公开仓库**，含企业名与人员姓名
4. **定期备份**。Docker 模式的库在命名卷里，备份方式：
   ```bash
   docker compose exec server cp /data/gmp.db /tmp/gmp.db
   docker cp gmp-audit-server:/tmp/gmp.db ./backup-$(date +%F).db
   ```
   再配 crontab 每天执行。**只存在同一台服务器上不算备份。**
5. **安全组只放行 8080**，不要把 22 之外的端口全开。3000 是后端容器内端口，**不对外暴露**（nginx 已代理）。
