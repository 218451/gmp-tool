# 云服务器部署方案

> 目标：让同事在**任何网络、任何时间**都能打开这个工具，不依赖您这台电脑。
>
> 与原工具的区别：原工具是单个 HTML 文件，GitHub Pages 免费托管；
> 本产品有后端与数据库，必须跑在一台**7×24 在线**的服务器上。

---

## 一、方案对比

| 方案 | 费用 | 关机影响 | 推荐度 |
|---|---|---|---|
| **A. 云服务器**（本方案） | 约 40~80 元/月 | **不受影响** | ✅ 推荐 |
| B. 内网穿透 | 免费~30元/月 | 您的电脑关了就连不上 | ⚠️ 临时演示可用 |
| C. 只在局域网用| 0 | 您的电脑关了就连不上 | ❌ 不满足需求 |

**为什么选云服务器**：审核员在企业现场跑，**未必跟您同一个网络**；而且审核报告涉及客户数据，放在云上比放在家里电脑上更安全（不依赖个人电脑的开关与网络）。

---

## 二、买什么服务器

| 项目 | 建议 | 说明 |
|---|---|---|
| 厂商 | 阿里云 / 腾讯云 / 华为云均可 | 选离审核现场近的地域 |
| 配置 | **2核 2G**，系统 Ubuntu 22.04 | 够跑，本工具很轻 |
| 系统盘 | 40G SSD | 含系统 + 应用 + 数据库 |
| 带宽 | 1~3 Mbps 固定带宽 | 够几十人同时用 |
| 预期月费 | **40~80 元** | 活动期新用户常有首年优惠 |

**推荐轻量应用服务器（ECS/Lighthouse）**，比 ECS 便宜、开通快。

## 三、部署步骤

### 步骤 1 · 准备环境

登录服务器（Windows 用 Xshell/PuTTY，Mac 用终端）：

```bash
# 安装 Node.js 22
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt-get install -y nodejs

# 确认版本
node -v   # 应为 v22.x
```

### 步骤 2 · 上传代码

在服务器上：

```bash
mkdir -p /opt/gmp && cd /opt/gmp
# 用 git 拉取（仓库是私有的，需先配好SSH 或改用上传方式）
git clone git@github.com:218451/gmp-tool.git .
cd gmp-增值评估工具
```

> 仓库当前是**私有**。若想让部署更简单，可在 GitHub 仓库设置里
> 临时改为 Private→ 保持不变 + 在服务器配 deploy key（只读）。

### 步骤 3 · 配置环境变量

```bash
cd /opt/gmp/gmp-增值评估工具/server
cp .env.example .env

# 生成强随机密钥
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

vi .env
# 至少改这三项：
#   DATABASE_URL="file:./v2.db"
#   JWT_SECRET="<上面生成的 64 位随机串>"
#   DEFAULT_ADMIN_PASSWORD="<您自己设的强密码>"
```

> ⚠️ **强烈建议现在换掉 admin 密码**：旧密码明文曾出现在启动脚本与文档中。

### 步骤 4 · 启动

```bash
cd /opt/gmp/gmp-增值评估工具/server
npm install
npx prisma db push --skip-generate
npx tsx prisma/seed.ts          # 灌入 200 条指导原则数据
cd ../web && npm install && npm run build
cd ../server && npx tsx src/index.ts
```

访问 `http://服务器IP:8780/` 确认能打开。

### 步骤 5 · 配开机自启（重要）

否则重启服务器后服务不会自动起来：

```bash
npm install -g pm2
cd /opt/gmp/gmp-增值评估工具/server
pm2 start src/index.ts --name gmp-audit --interpreter npx --interpreter-args "tsx"
pm2 save
pm2 startup# 按提示执行它给出的那条命令
```

### 步骤 6 · 开防火墙 + 域名 HTTPS

**服务器自身的安全组**放行端口（腾讯云/阿里云控制台里配，不是 Windows 防火墙）：

| 端口 | 用途 |
|---|---|
| 22 | SSH |
| 80 | HTTP |
| 443 | HTTPS |

系统防火墙：

```bash
ufw allow 22/tcp && ufw allow 80/tcp && ufw allow 443/tcp
ufw enable
```

### 步骤 7 · 备份数据库（务必做）

数据库是全部业务数据，**丢了就找不回来**：

```bash
mkdir -p /opt/gmp/backup
cat > /opt/gmp/backup.sh << 'EOF'
#!/bin/bash
cd /opt/gmp/gmp-增值评估工具/server
cp prisma/v2.db "/opt/gmp/backup/v2-$(date +%Y%m%d-%H%M).db"
find /opt/gmp/backup -name "v2-*.db" -mtime +30 -delete
EOF
chmod +x /opt/gmp/backup.sh

# 每天凌晨 3 点自动备份
crontab -e
# 加一行：
# 0 3 * * * /opt/gmp/backup.sh
```

> 💡 更稳妥：把备份同步到对象存储或另一台机器。**只存在同一台服务器上不算备份。**

## 四、部署后验证清单

| 检查项 | 预期 | 命令 |
|---|---|---|
| 服务在跑 | 200 | `curl http://127.0.0.1:8780/api/health` |
| 数据库连上 | `"db":"up"` | 同上，看返回内容 |
| 指导原则已灌 | 200 条 | 登录后看条款分级页 |
| 自启已配置 | 重启服务器后仍能访问 | `pm2 list` |
| 备份已配置 | 定时任务存在 | `crontab -l` |
| 外网可访问 | 手机流量能打开 | 用手机流量试 |

## 五、常见问题

**Q：启动报better-sqlite3 编译失败**
装构建工具：`apt-get install -y python3 make g++`

**Q：忘记 admin 密码**
在服务器上重置：
```bash
cd /opt/gmp/gmp-增值评估工具/server
node -e "const b=require('bcryptjs'),{PrismaClient}=require('@prisma/client');const p=new PrismaClient();
(async()=>{await p.user.update({where:{username:'admin'},data:{passwordHash:b.hashSync('新密码',10)}});
await p.\$disconnect();console.log('已重置')})()"
```

**Q：AI 报告不生成**
服务器上没配 DeepSeek Key，系统会自动降级为规则引擎，**功能不受影响**，只是分析文本没那么灵活。

**Q：能不能用 Docker**
可以，仓库已含 `docker-compose.yml` 与两个 `Dockerfile`：
```bash
docker compose up -d
```
（后端 Dockerfile 已从 alpine 改为 bookworm，避免 better-sqlite3 原生编译失败。）

## 六、安全提醒

1. **admin 密码务必更换**，旧密码已暴露过
2. **`.env` 不要提交到 Git**，仓库已配 `.gitignore`
3. **不要把数据库文件 `v2.db` 传到公开仓库**，含企业名与人员姓名
4. **定期备份**，并把备份存到服务器之外
